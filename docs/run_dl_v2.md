# run_dl_v2.py — 技术文档

## 1. 概述

`run_dl_v2.py` 是基于深度学习的**人体活动识别（HAR）分类流水线**，在 v1 基础上做出两项关键改进：

- **恢复重力倾角信息**：将 UCI HAR 数据集中被丢弃的 `total_acc`（含重力分量的加速度）重新纳入 CNN 输入，使模型能够区分坐/站/躺等静态姿势
- **完整实验结果产出**：训练曲线、混淆矩阵、类别 F1 对比图自动生成，评测报告自动保存为 Markdown 文档

支持两个数据集：**UCI HAR**（6 类活动，6 轴传感器）和 **WISDM**（5 类活动，3 轴加速度计）。

---

## 2. 诞生过程

这一节记录 `run_dl_v2.py` 从问题发现到最终方案的完整思维链。

### 2.1 起点：静态姿势分类不准

项目最初使用 `main.py` 中的传统流水线——手工时域/频域特征 + KNN/SVM/RF。整体准确率尚可（RF ~90%），但**混淆矩阵揭示了一个结构性问题**：SITTING 和 STANDING 之间的混淆严重。

这两种活动都是静态姿势，加速度和角速度信号都接近零。传统手工特征（均值、方差、过零率、频谱质心）在这两种姿势上产生几乎相同的值——模型缺乏区分它们的"抓手"。

### 2.2 第一次假设：姿态角能解决问题

直觉上，坐着和站着时身体的倾斜角度不同：站着直立，坐着可能微前倾。如果能显式地提取手机的俯仰角和翻滚角，模型就有了区分两种姿势的物理依据。

于是诞生了**方案一**：在 `feature_extraction.py` 中新增 `extract_orientation_features()`，计算 pitch、roll、重力分量占比等 9 维特征。这些特征直接编码了"手机如何倾斜"。

### 2.3 深度学习引入与迭代

同时引入了三个深度学习模型（MLP / CNN1D / CNN-LSTM），写入 `dl_models.py`。然而初次训练后发现**上下楼梯的准确率反而比传统方法低**。

原因分析：CNN 只看到原始时域波形，没有频率信息。上下楼梯的核心差异在频域（步频、谐波结构），CNN 要从头"学会做 FFT"需要极大样本量。

针对这个问题，升级了 `dl_models.py`：
- **ResNet1D**：多尺度并行卷积核（3/5/7），同时捕获细粒度冲击和粗粒度步态周期
- **Focal Loss**：自动把训练算力集中在难分样本
- **信号增强 + Cosine 退火**：增加多样性，稳定收敛

### 2.4 关键发现：total_acc 被丢弃了

在代码审查中发现 `load_har_data()` 只加载了 `body_acc` 和 `body_gyro`，**跳过了 `total_acc`**。

UCI HAR 数据集中有三类惯性信号：

| 信号 | 含义 |
|------|------|
| `body_acc` | 身体加速度（已用低通滤波移除重力分量） |
| `body_gyro` | 角速度 |
| `total_acc` | **总加速度（含重力）** — 编码手机的空间朝向 |

重力向量是区分静态姿势的关键物理量。v1 的 CNN 只能看到加速度变化（运动），看不到恒定的重力方向（姿态）。于是决定创建 v2，将 `total_acc` 的三轴数据纳入 CNN 输入。

### 2.5 反思：预期与现实的差距

v2 构建完成后，一个需要正视的问题是：**加入 total_acc 是否真的能提升 SITTING 和 STANDING 的分类效果？** 下一节对此进行详细分析。

## 3. 重力倾角信息的局限：为什么 sitting/standing 准确率可能不升反降

这是一个反直觉的问题——"更多的信息"为什么可能导致更差的结果？答案藏在 UCI HAR 数据集的采集方式中。

### 3.1 数据集采集姿势

UCI HAR 数据集使用 **Samsung Galaxy S II 固定在腰部（waist）** 采集。这是理解问题的关键。

```
站立（STANDING）                坐着（SITTING）

   ┌─ 躯干直立 ─┐                  ┌─ 躯干直立 ─┐
   │            │                  │            │
   │   📱 腰部   │                  │   📱 腰部   │
   │            │                  │            │
   │   ┃┃       │                  │   ══       │
   │   ┃┃ 腿    │                  │   ══ 腿    │
   └────────────┘                  └────────────┘

   重力向量: ↙                     重力向量: ↙
   (几乎相同)                       (几乎相同)
```

站立和坐着时，**躯干都保持近似直立**。手机固定在腰部，其绝对空间朝向在这两种姿势下几乎一致——重力在三个轴上的分量非常相似。

### 3.2 信号层面的定量分析

设窗口信号为 `s(t) = DC + Δs(t)`，其中 DC 是重力导致的恒定分量，Δs(t) 是微小的身体晃动。

| | STANDING | SITTING |
|---|---|---|
| **DC 分量（重力）** | 大（~9.8 m/s² 分配在三轴上） | **几乎相同** |
| **Δs(t)（晃动）** | 站姿微调（踝策略），小幅摆动 | 坐姿微调，频率/幅度略不同 |
| **body_acc** | ≈ Δs(t)，均值 ≈ 0 | ≈ Δs(t)，均值 ≈ 0 |
| **total_acc** | DC + Δs(t) | DC' + Δs'(t)，DC ≈ DC' |

问题在于：

1. **DC 分量占主导**：total_acc 中 99% 的信号能量来自恒定重力，只有不到 1% 是微小的晃动差异
2. **DC 不具区分性**：两种姿势的 DC 几乎相同（躯干直立+腰部固定），CNN 看到的是两个极其相似的强信号
3. **有效信号被淹没**：真正有区分力的 Δs(t) 差异（坐姿晃动 vs 站姿晃动）被 DC 的巨大振幅掩盖

### 3.3 CNN 的视角

从 CNN 的角度看，`total_acc` 的三个通道在 sitting 和 standing 的窗口上呈现出几乎完全相同的波形——一个平坦的直线（DC）加上微小的波纹（晃动）。

```
total_acc_z 通道（腰部垂直轴）：

STANDING:  ───────────────────────────────────────  (~9.5 m/s²)
           微小的站姿晃动 ↑   ↑  ↑    ↑

SITTING:   ───────────────────────────────────────  (~9.5 m/s²)
           微小的坐姿晃动  ↑  ↑   ↑       ↑
```

CNN 的第一层卷积学到的是：这两个类别在 `total_acc` 上的模式几乎相同 → **`total_acc` 通道对区分 sitting/standing 的贡献接近于零**。更糟的是，这 3 个额外通道增加了 50% 的输入维度，可能稀释梯度信号，使优化更容易陷入次优解。

### 3.4 真正有用的区分信息在哪里

站立和坐着的本质差异不在静态倾角，而在**微动态特征**：

| 特征类型 | 站立 | 坐着 |
|---------|------|------|
| 身体晃动幅度 | 较大（踝关节策略维持平衡） | 较小（椅子提供支撑） |
| 晃动频率 | ~0.5–1 Hz | 更低，不规则 |
| body_acc 方差 | 略高 | 略低 |
| 腰部倾角变化 | 微小但持续 | 几乎为零 |

这些差异体现在 `body_acc` 的**方差、过零率、频带能量**等时频特征中，而非 `total_acc` 的 DC 分量中。v1 已经包含了这些特征，所以 v2 加入 total_acc 后 sitting/standing 的表现可能反而下降。

### 3.5 total_acc 真正有效的场景

这并不是说 total_acc 没有价值。它在以下场景中至关重要：

- **LAYING（躺下）**：手机从直立变为水平，重力从 z 轴完全转移到 x 或 y 轴 → **total_acc 的各轴 DC 值发生 90° 翻转**，这是最强的区分信号
- **动态活动中夹杂的短暂静止**：走路中停顿 vs 跑步中停顿，total_acc 提供姿态上下文
- **WISDM 数据集**：手机放在裤袋中（而非腰带上），坐姿会让大腿倾斜 → 手机倾角确实发生变化

### 3.6 解决思路

针对 UCI HAR 的 sitting/standing 困境，更有效的方向可能是：

1. **对 body_acc 提取更精细的微动态特征**：如 jerk（加加速度）的统计量、晃动频段的窄带能量
2. **增大窗口长度**：当前 2.56s 可能不足以捕获完整的晃动周期
3. **减轻 total_acc 通道的权重**：通过注意力机制让模型自己学习哪些通道对哪些类别有用
4. **使用对抗训练或对比学习**：显式地拉近同类别样本、推远不同类别样本

## 5. 关键设计

### 5.1 CNN 输入通道设计（HAR）

| 信号 | 通道数 | 物理含义 | 对静态姿势的价值 |
|------|--------|----------|:---:|
| `body_acc_{x,y,z}` | 3 | 身体加速度（重力已移除） | 反映纯运动 |
| `body_gyro_{x,y,z}` | 3 | 角速度 | 反映旋转/转向 |
| `total_acc_{x,y,z}` ★ | 3 | 总加速度（含重力） | **编码手机倾角** |

v1 只有前 6 通道，`total_acc` 被丢弃。对于 SITTING/STANDING/LAYING 这类静态姿势，`body_acc` 和 `body_gyro` 的值都接近零，唯一的区分信息就是重力在三个轴上的分量——这正是 `total_acc` 提供的信息。

CNN 的 9 通道输入形状为 `(N, 9, 128)`，其中 128 是 2.56s 窗口在 50Hz 采样下的时间步数。

### 5.2 姿态角特征

在手工特征提取中，`extract_orientation_features()` 从 `total_acc_{x,y,z}` 计算以下 9 维特征：

- **俯仰角 (Pitch)**：`arctan(ax / sqrt(ay² + az²))`，前倾/后仰 — 区分坐（微前倾）与站（直立）
- **翻滚角 (Roll)**：`arctan(ay / sqrt(ax² + az²))`，左右倾斜
- **重力分量占比**：`|mean_i| / (|mean_x| + |mean_y| + |mean_z|)`，各轴承载重力的比例

这些特征直接编码了手机（及人体）的空间朝向，是区分静态姿势的物理本质。

### 5.3 四个深度学习模型

| 模型 | 输入 | 结构特点 | 适用场景 |
|------|------|---------|---------|
| **MLP** | 手工特征向量 (~120 维) | 3 层全连接 [256,128,64] + BatchNorm + Dropout | 依赖人工特征工程的 baseline |
| **CNN1D** | 原始信号 (N, C, T) | 3 层 Conv1d [64,128,256] → FC | 自动学习局部时序模式 |
| **CNN-LSTM** | 原始信号 (N, C, T) | CNN 提取 → 双向 LSTM 建模长程依赖 | 捕获步态周期等长时模式 |
| **ResNet1D** ★ | 原始信号 (N, C, T) | 多尺度残差块（并行 kernel=3,5,7）+ 跳跃连接 | 同时捕获细粒度冲击和粗粒度周期 |

所有 CNN 类模型共享相同的训练增强策略。

### 5.4 训练策略

每个模型使用统一的高级训练配置：

| 技术 | 配置 | 作用 |
|------|------|------|
| **Focal Loss** | γ=2.0，自动类别权重 | 聚焦难分样本（上下楼梯混淆），防止被大量简单样本淹没 |
| **Cosine 退火 + Warmup** | 5 epoch warmup → cosine decay | 比 ReduceLROnPlateau 更平滑的收敛 |
| **信号增强** | 高斯噪声 + 时间偏移 + 幅值缩放 | 增加楼梯/姿态变化等少样本类别的多样性（仅 CNN 类模型）|
| **AdamW** | lr=0.001, weight_decay=1e-4 | 正确的权重衰减解耦 |
| **梯度裁剪** | max_norm=1.0 | 防止训练震荡 |
| **Early Stopping** | patience=20 | 防止过拟合 |

## 7. 使用方法

```bash
# 默认：HAR + WISDM，全部 4 个模型，100 轮
python run_dl_v2.py

# 仅 HAR，仅 ResNet
python run_dl_v2.py --har --resnet

# 仅 WISDM，全部模型，150 轮
python run_dl_v2.py --wisdm --epochs 150

# 仅 CNN-LSTM
python run_dl_v2.py --cnnlstm

# 查看所有选项
python run_dl_v2.py --help    # (暂无 --help，参数见下表)
```

| 参数 | 说明 |
|------|------|
| `--har` | 仅运行 HAR 数据集 |
| `--wisdm` | 仅运行 WISDM 数据集 |
| `--all` | 强制运行两个数据集（默认行为） |
| `--mlp` | 仅训练 MLP |
| `--cnn` | 仅训练 CNN1D |
| `--cnnlstm` | 仅训练 CNN-LSTM |
| `--resnet` | 仅训练 ResNet1D |
| `--epochs N` | 最大训练轮数（默认 100） |

## 9. 与 v1 的差异对照

| | run_dl.py (v1) | run_dl_v2.py (v2) |
|---|---|---|
| HAR CNN 通道 | 6 (body_acc + body_gyro) | **9** (body_acc + body_gyro + total_acc) |
| 姿态角来源 | body_acc（重力已移除） | **total_acc**（含重力） |
| HAR 特征数 | ~81 维 | **~120 维**（多 3 轴信号特征） |
| 损失函数 | Focal Loss + 类别权重 | 同 v1 |
| 学习率调度 | Cosine + Warmup | 同 v1 |
| 训练曲线图 | 无 | **有**（loss + acc 双轴） |
| 混淆矩阵 | 无 | **有**（数量 + 归一化比例） |
| 类别 F1 对比 | 无 | **有**（横向柱状图） |
| 结果文档 | 终端输出 | **自动保存 `results_summary.md`** |
| 默认 epochs | 80 | **100** |
